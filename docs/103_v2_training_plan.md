## 0. 5분 요약 — 무엇을 바꾸고 왜 바꾸나

**c3는 성공했다.** 32,000 iter 완주, vx 2.5 + 도메인랜덤화 만배 조건에서 **낙상 0**, 576 에피소드 평가에서 **성공률 100 %**,
전진 추종 오차가 2.4 m/s에서도 0.17 m/s로 평탄. 그러니 V2는 "고장난 걸 고치는" 계획이 아니라 **"낭비와 눈속임을 걷어내고, 남은 결함 두 개를 잡는"** 계획이다.

### 걷어낼 낭비 세 가지
1. **커리큘럼이 iter를 버린다.** 명령 범위를 넓힐 때마다 정책은 **20 iter 안에** 새 수준에 적응하는데, 우리는 매번 **4,000 iter**를 기다렸다. 3,980 iter가 그냥 흘러간다.
   → *고정 시간표* 대신 **성적표로 진급**시킨다(조건 충족 시 다음 단계, 최소 800 · 최대 3,000 iter).
2. **탐색 노이즈가 되돌아오지 않는다.** 학습 중 정책은 일부러 손을 떨어 여러 동작을 시도하는데(σ), 이 떨림이 0.30 → 0.47로 **커지기만 하고 줄지 않았다**. 배포 때는 떨림을 끄므로, 마지막까지 떨면서 배운 정책을 안 떠는 상태로 내보내게 된다.
   → 학습 후반에 **떨림을 서서히 줄인다**(entropy 계수 어닐링).
3. **지표가 거짓말을 했다.** `error_vel_xy`는 평균이 아니라 합÷400이라 **실제 오차의 2.5배**로 보이고, 못 걸어 넘어질수록 오히려 **좋아 보였다**(초기 0.02–0.08).
   → 정직한 지표 두 개를 이미 추가했다(`_mean`, `_steady`). 논문·리포트는 이걸 쓴다.

### 잡을 결함 두 가지
4. **로봇이 느린 명령을 무시한다.** 0.25 m/s로 걸으라고 하면 **가만히 서 있는다**(달성률 0 %). 버그가 아니라 **보상 산수의 결과**다 —
   그 속도에서는 걷는 이득(+0.41/step)보다 걷는 비용(−0.9/step, 절반이 `action_rate`)이 커서 **서 있는 게 점수가 높다**.
5. **쪼그려 걷고 발로 밀지 않는다.** 사람은 디딤발을 펴고 발끝으로 밀어내는데(발목 −17°), 우리 로봇은 무릎을 −45~−50° 굽힌 채 걷고 발목은 −5°에서 그친다.
   그래서 사람 보행의 특징인 **M자 지면반력**이 안 나온다. 이게 "사람처럼 걷기"의 가장 큰 남은 격차다.

### 순위가 바뀐 것 (중요)
c3 도중 "RP 발목 모터가 82 %로 포화한다"고 보고했는데 **좌표계 오류였다**(RP도 모터는 크랭크에 있다). 바로잡으면 **두 arm 모두 활용률 0.44–0.55, 포화 ≤0.03 %**다.
→ **모터에 여유가 충분하므로 "T-N 토크 여유 보상항"은 더 이상 1순위가 아니다.** 대신 위의 4·5번이 1순위가 된다.

## 3. 스케줄

### 3a. Phase 1 — flat, DR off, **성적표로 진급하는 커리큘럼**
> *쉽게*: 예전엔 "4,000 iter 지나면 무조건 다음 단계"였다. 이제는 **"잘하면 다음 단계, 못하면 더 연습"**이다.

| 단계 | vx | **vy** | yaw |
|---|---|---|---|
| S0 | ±0.8 | **±0.5** | ±0.5 |
| S1 | ±1.2 | **±0.6** | ±0.8 |
| S2 | ±1.6 | **±0.7** | ±1.0 |
| S3 | ±2.0 | **±0.85** | ±1.0 |
| S4 | −2.0/+2.5 | **±1.0** | ±1.0 |

**진급 조건**(100-iter 이동평균, 셋 다 충족): ① `error_vel_xy_steady` ≤ 직전 단계 정착값 × 1.10 ② `fell_over` ≤ 0.005 ③ 최소 dwell **800** iter.
**최대 dwell 3,000 iter** 초과 시 강제 진급 + 경고 로그. 예상 P1 **8k–14k**(기존 고정 20k).

### 3b. Phase 2 — DR 램프 + 소화 + **떨림 줄이기**
- DR 0 → 1을 P1 종료 후 **8,000 iter**에 걸쳐, 이후 **4,000 iter 소화**(총 P2 ≈ 12,000).
- **`entropy_coef` 0.01 → 0.002 선형 어닐링**(P2 전 구간).
- ⚠ **함정**: P1 길이가 가변이라 DR 시작 iter를 손으로 못 박으면 안 된다. 2026-07-15에 P1이 짧아 **DR이 0.33에 고착**한 사고가 있었다 → 런처가 P1 실측 길이에서 `PYG_DR_START_ITER`/`END_ITER`를 **자동 계산**해야 한다.
- 총 **20k–26k iter**(기존 32k), 16384 env·단독 3.2 s/iter → **18–23 h/arm**.

## 4. 재현 절차 (순서대로)
> *쉽게*: 1–3번은 "로봇 파일 다시 만들기", 4–6번은 "바꿀 것 준비하기", 7–8번은 "연습 삼아 짧게 돌려보고 진짜 학습".

```bash

# 2) 독립 파서로 검증 — 여기서 숫자가 docs/102 §4a 표와 같아야 한다

# 3) 질량 불확실성 → DR 범위 (구조적 하한 ±5 → ±7 %, 케이블·미체결 나사 흡수)
mujoco-sim/mjlab/.venv/bin/python3 tools/robot_model/mass_dr.py --samples=3000
```
4. **연구 노트 작성**(리워드 변경 전 훅이 강제): V1(저속 무시), V2(push-off). `docs/reward_research/`에 근거 노트 없으면 편집이 차단된다.
5. **구현**: 게이트형 커리큘럼(V3), entropy 어닐링(V4), critic DR 관측(V9), IMU 관측(V10) — 전부 `PYG_*` 플래그로 **기본 OFF** 후 개별 검증.
6. **런처 수정**: P1 실측 길이 → DR start/end 자동 계산.
7. **스모크 런**: 1024 env · 1,500 iter. 확인 항목 = 게이트 전이 로그, DR 계산값, 새 지표 3종 동시 로깅, 낙상 0.

## 5. 게이트·측정 프로토콜
1. 게이트마다: `snapshot_review.py` 판정행 + **평가기 축소판**(3시나리오 × 32 env, CPU 8분/arm) + `impact_probe`(200 Hz) + `dr_factor`·`lin_vel_x_max` 동시 기록.
2. **단일 롤아웃 프로브를 판정 근거로 쓰지 않는다**(V12).
3. 완주 후: 평가기 **전체 격자**(속도별로 3시나리오씩 쪼개서 — 한 번에 25개는 RAM이 터진다) + `measure_full.py` fc/fcp(15 s dwell, 전체 박스) + §7 모터활용(T-N, **모터축으로 사상 후**).
4. 설계값: 열 = RMS × 1.15, 순시 = P99 × 1.25, **raw peak 단독 금지**(knee τ_max 120.0은 클립 아티팩트).

## 6. 리스크·미검증
- **실물 대조 0건.** 관성·마찰·지연 전부 CAD/데이터시트/벤치 값이다.
- V1·V2는 **리워드 변경**이라 게이밍 위험이 가장 크다. 반드시 +800 iter · 1024 env 시험으로 해킹 모드를 먼저 본 뒤 본 런에 넣는다(soft-landing이 이 절차로 선형형 해킹을 잡았다).

- η_drive 0.80이 전력 추정 최대 오차원(±15–20 %) — CoT 절대값보다 arm 간 비를 쓸 것.
