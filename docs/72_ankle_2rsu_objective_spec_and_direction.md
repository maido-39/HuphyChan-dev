## §0 결론 (rev3 — 요동각 축 정정, docs/71 §15)

1. **rev2의 ROM 축소·재학습 필수 결론 철회**: 발측 JS6는 클레비스 볼트=발 좌우축 — 볼트축 회전(pitch 추종) 무제한, ±20°는 로드의 **좌우 기울기**(arcsin|u·x̂_foot|)에만 적용(사용자 정정, rev2까지의 수직원뿔 모델은 오류).
2. **현행 full ROM(pitch −50~+30 × roll ±20)이 JS6 ±20으로 성립**(+3.8%). **roll ±15면 +27.6% 마진, 피크층까지 양수(+7%)** — PYG_ANKLE_ROLL15(±15) 실험이 마진 확보 수단(플릿 |roll|≤15 사용 98.6%). 병목 축은 roll 하나.
3. 수요풀 v4(13정책 221k, cant 제외)·감사 36건 수정(v6→v7 파이프라인)·φ0 분기 자유화는 유효. freeze 게이트(재학습 불필요해졌으나 **재측정 후 v7 재실행**)는 유지.

## §3 설계 방향 (rev3 — full ROM 성립)

### §3a 확정 방향
- **ROM: 현행 유지**(pitch −50~+30). **roll: ±20 성립(+3.8%, 얇음) vs ±15(+27.6%, 피크 커버) — ±15 권고**, PYG_ANKLE_ROLL15 학습검증으로 확정(플릿 사용 |roll|≤15 = 98.6%).
- 권고기하(v7 full×±15 승자): A_r 61.2 · B_r 61.7 · RP_B 57.1 · RP_r 46.7 ≈ A_h 45.0(횡 정렬) · B2RP 175.7 · RP_h 9.8 · A_L 275.1 · B_L 174.3. 마진: latF 14.5°/20 · torque +29% · tn +48% · rod +75%.
- 로드 양단 트위스트 적합성 검증됨(Δψ ±12° vs 여유, 최소차 +18.6°, 조립 τ0≈0°).
- 확인 잔여: **CAD에서 발측 클레비스 볼트 방향=발 좌우축 확정**(본 스펙의 전제).

### §3d 스토퍼 하중 경로 (감사 critical)
ROM 캡이 사용 밀집대역에 접근할수록 스토퍼 접촉이 일상 하중이 됨(구속토크 P99 148–160, peak 490–630 N·m — 모터클립 우회). **발–정강이 직접 패드 경로(우레탄 범퍼, 에너지 기반 사이징)를 Tier-0 전제로 승격**하고, 로드 경유 시나리오(로드력 P99 1.33 kN/peak 5.3 kN)를 컨틴전시 하중케이스로 검증. CAD에서 패드 경로 미확보 시 이 최적화 결과 전체가 무효.

**✅2026-08-17 정량 종결 (docs/78 §12~§14, `tools/ankle_stop_residual.py`)** — 본 항의 핵심 주장
두 가지가 각각 확인·정정됐다.
- ✅**"스토퍼 접촉 = 일상 하중"은 맞았다**: 31개 롤아웃 실측에서 pitch가 전 프레임의
  **9.5 %**, roll이 **7.7 %** 동안 캡에 붙어 있다. → 정적 강도만이 아니라 **마모·피로**가
  판정 항목(docs/78 §14-2).
- ⚠**수치는 4~6배 과대**였다: 인용된 P99 148–160 / peak 490–630 N·m은 docs/64 §8c-RT의
  값이고 §8i 기준점 버그를 포함한다. 보정 후 확정 설계기준(캡 접촉 프레임만)은
  **pitch 상시 172.5 / 설계 peak 379.0 N·m · roll 82.1 / 153.8 N·m**(31 롤아웃·전 프레임).
- ✅**"발–정강이 직접 패드 경로 Tier-0" 지시는 유지**: 크랭크측 스토퍼 시 로드력
  **9,325 N → JS6 $s_0$ 0.54**로 정적 정격을 1.9배 초과한다(로드 경유 **금지** 확정).
  요구 단면적은 롤 짐벌 반경 60 mm에서 **전단 86 mm²**(SF 2.0, 6061-T6).
- ⬜**미결로 남는 것**: 우레탄 범퍼 **에너지 기반 사이징**(본 항이 요구한 방법)은 미착수 —
  현 값은 강체 접촉 정적 기준이다. CAD 패드 경로 확보 여부도 여전히 CAD 게이트.

## §4 목적함수 명세 v6 (사전식 · Deb 3규칙)

**구조** (docs/60 Deb 원칙: hard와 목적 절대 혼합 금지, 페널티 합성 금지, best-feasible-ever 유지):

> **T0 hard** (위반 시 infeasible, 위반량 등급형 합산으로 순위) → **T1** peakScore = min(0, min 피크마진) 최대화(커버는 best-effort, 동률 허용오차 5pp) → **T2** p99Score = min(P99/그리드 마진) **최대화**(마진 최대화가 목적, 통과가 아님) → **T3** 동률해소: 로드 축력 RMS ↓ → 크랭크 스윕 부피 ↓

### 데이터 명세 (v6)

- 수요셋(rev2): **v4 풀 = 13정책·25파일·221,650샘플**(전 _fc/_fcp; cant\*·p2f\*(낙상오염)·p2r-v1(지형혼합) 제외; `build_ankle_demand_v4.py`) = 스크리닝 기준. freeze용은 **재학습 정책에서 재측정**(fc+fcp, flat/rough 분리, 15 s dwell, PYG_BOX, 멀티시드 CI).
- 극값 보존 풀: **6열 전부**(ω 포함, 현재 4열 — tn_pk 표본 누락 가능) + 문서와 코드 백분위 일치(15%); 박스별 풀-샘플 대조 assert.
- 클립(\|τp\|≥89.5)=**검열된 수요**(부재 아님): 재학습에 effort limit 81 N·m 번들 → 검열 원천 제거. 그 전까지 검열율·근접점유율([80,89.5]) 병기.
- ROM 밖 표본은 clip이 아니라 **제외**(§8g 규칙 유지).

### 옵티마이저

DE/rand/1/bin (NP 120, F 0.6, CR 0.9) + Sobol 스크리닝 병행, 시드 ≥3(freeze는 100), 정체 이중 조기종료. 게이트 실패는 상수 센티널 대신 **등급형 위반량**(스택 초과량·폐합 잔차·윈도우 초과도) — 0.01~0.02% feasible 영역에서 평탄 지형 방지. φ0 ∈ {0,180} 이산 변수 + 분기 연속성 추적(그리드 인접 \|Δφ\| 상한 assert).

## §6 프로세스 게이트 (freeze 체크리스트)

1. **[스크리닝]** 구정책 필터 리플레이 = 후보 축소용만(pro-shrink 편향 명시). ✅ 완료 — v4 풀·80박스 프런티어·v6 4박스 feasible(§3a).
2. **[결정]** ✅완료(rev2): JS6 ±20 하드(사용자) · ROM 후보 = §3a 표(권고 [−15,+20]×±10) — 최종 박스 선택만 남음.
3. **[재학습]** 확정 ROM 캡 + effort 81 + 캡근접 소프트마진 번들, 수렴까지 (Windows 3090 복구 후 또는 로컬). flat·rough 양쪽, rough 게이트 A/B 감시.
4. **[재측정]** fc+fcp · flat/rough 분리 · 15 s dwell · PYG_BOX · 멀티시드 · dr_coverage/낙상 수 · 스토퍼 접촉 이벤트 플래그 포함.
5. **[재최적화]** v6 스펙으로 DE(φ0 변수 포함), 최적해 41×21+코너 최종검증, §1b 표 형식 마진 보고.
6. **[CAD 게이트]** 패드 경로 · RP_h 스택 · H7/H8 클리어런스 · 크랭크측 로드엔드 C0 카탈로그 확정.
