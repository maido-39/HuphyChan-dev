# HUPHY 코드 수정 장부

> 사용자 지시 (2026-09-09): "HUPHY Repo 의 코드를 수정해야 한다면, 브랜치안에서 작업해야
> 하며, **왜 무엇을 어떻게 어디를 누가** 수정했는지 투명하게 장부로 기록한다."

HUPHY 는 우리 저장소가 아닙니다. 그래서 규칙이 둘 있습니다.

1. **main 을 건드리지 않는다.** 모든 수정은 가지(branch)에서만 하고, 그 가지 이름을 여기 적는다.
2. **여기 적히지 않은 수정은 없다.** 로봇에서 급하게 고친 것도 포함한다. 되돌린 것은 지우지
   않고 취소선으로 남긴다.

로봇 쪽 원본 위치: `syaro@10.8.0.14:/home/syaro/Human-Pygmalion/HUPHY`

## 현재 가지 상태

| 가지 | 무엇 | 상태 |
|---|---|---|
| `bench-rate-limit` | 벤치용 속도 제한 (2026-09-08) | **로봇에서 지금 이게 돌고 있음** |
| `rate-limit-from-datasheet` | 데이터시트 기준 속도 제한 | 만들어 둠, 미적용 |

## 기록

각 항목은 **왜 / 무엇을 / 어디를 / 어떻게 / 누가 / 되돌리는 법** 순서로 적습니다.

### 001 — (기록 없음) 2026-09-09 사인 스윕 실험

**이 실험에서는 HUPHY 코드를 한 줄도 고치지 않았습니다.** 남기는 이유는, 고치지 않았다는
사실도 장부에 있어야 나중에 "그때 뭘 건드렸나"를 되짚을 수 있기 때문입니다.

실험(`docs/experiments/2026-09-09_sim_vs_real_sine_sweep.md`)에서 한 것은 전부 읽기와
우리 저장소 쪽 수정입니다:

* 로봇에는 **읽기만** 했습니다 — 돌고 있는 프로그램의 실행 인자 확인(`pgrep`), 소스에
  smoothing/필터가 있는지 검색(`grep`). 파일을 쓴 적 없습니다.
* 로봇 프로그램은 **재시작하지 않았습니다.** 실험 내내 같은 프로세스가 돌았습니다.
* 우리 저장소 쪽 수정은 `Viewer-Prototype` 가지에 있고, 아래 세 가지입니다:
  기록에 실측 각도 추가(`schema.py`/`record.py`/`sim_core.py`), 사인 스윕 도구 추가
  (`tools/pygviewer/scripts/sine_sweep_ab.py`), 이득/지연 분석.

**확인된 로봇 실행 인자** (읽기만, 2026-09-09):

```
huphy_remote_motion --config HUPHY/config/robot_bench.yaml --limb left_leg
  --enable hip_yaw,knee --listen 0.0.0.0:9872 --telemetry 192.168.20.177:9870
  --kp-max 50 --kd-max 2.5 --deadman-s 0.2 --hold-s 86400 --return-s 2
  --allow-uncalibrated
```

이 중 `--kp-max 50 --kd-max 2.5` 가 이득 사슬의 두 번째 상한입니다(첫 번째는 뷰어 쪽 30/1.5
이고, 더 낮은 쪽이 이기므로 실제로 모터에 도착하는 값은 30/1.5).

### 002 — 예정: 로봇이 자기 시각을 남기게 하기

**아직 하지 않았습니다.** 계획만 적습니다.

**왜.** 명령이 실물에 도착하기까지 80 밀리초가 걸리는데(실측), 예상 경로 합은 36~44
밀리초입니다. 나머지 36~44 밀리초가 어디인지 **로봇 밖에서는 가를 수 없습니다** — 로봇이
"몇 시에 패킷을 받았고, 몇 시에 모터에 썼는지"를 스스로 말해야 합니다.

**무엇을.** 이미 로봇이 보내는 진단 패킷에 숫자 두 개를 더합니다: 마지막으로 받아들인 명령
패킷의 수신 시각, 그리고 그 명령을 모터에 쓴 시각. 새 통로도 새 포트도 만들지 않습니다.

**어디를.** 로봇 쪽 수신·송신 경로 한 곳씩. 정확한 파일은 착수 시 여기에 적습니다.

**어떻게.** 새 가지 `latency-instrumentation` 을 `bench-rate-limit` 에서 따서 작업합니다.
제어 흐름은 건드리지 않고 **읽어서 내보내기만** 합니다 — 지연을 재려고 지연을 만들면 안 됩니다.

**되돌리는 법.** 가지를 버리고 `bench-rate-limit` 로 되돌린 뒤 프로그램 재시작.

**착수 전 확인할 것.** 프로그램을 재시작하면 그동안 모터 토크가 끊깁니다. 벤치에 사람이
있을 때, 그리고 사용자가 동의한 뒤에만 합니다.
