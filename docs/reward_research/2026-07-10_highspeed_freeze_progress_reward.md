# 2026-07-10 · 고속 명령 "얼어붙음" 근본원인 + 진행보상(A) 수정

**증상**: flat25(2.5 커리큘럼) 정책이 평지·무DR에서 **cmd 2.0→달성 0.10 m/s(5%), cmd 2.5→0.03(1%)**로 정지. 1.5까지는 걸음(0.94). 학습 error_vel_xy 2.3.

**HW 아님 (실측)**: 얼어붙을 때(cmd 2.5) 관절 토크 RMS knee 27/rated40=68%·hip_pitch 10%·ankle_pitch 60%, 속도 max knee 53/143rpm=37%·hip_pitch 22/143=15%. **토크 ~50%·속도 ~30%만 사용** = 물리적 여유 대량. 정책이 정지를 "선택".

**근본원인 (수식 확정)**: `track_linear_velocity = exp(-err²/std²)`, **std=0.5** (rewards.py:34, weight 2.0). err별 보상: 0.5→0.37, 1.0→0.018, 1.5→1e-4, 2.0→1e-7, 2.5→1e-11. ⇒ **오차>~1에서 보상·gradient 완전 소멸.** cmd 2.5서 0.03이든 1.0이든 추종보상 둘 다 ≈0 → "더 빨리 가라" 신호 없음 + 속도 유도 다른 항 전무(grep 확인) → 남는 신호는 낙상위험·effort 페널티 → **최적해=정지.** 절벽(1.5→2.0)이 정확히 exp 사망 지점. 프로젝트가 원래 커리큘럼 1.5 캡한 근본이유와 동일: **좁은 exp-추종만으로는 도달불가 목표를 밀 수 없음.**

**수정 = A(선형 진행보상) + std 확대**:
- **A 신규 `track_lin_vel_progress`**: `min(v_xy·cmd̂, |cmd|)` — 명령방향 속도를 명령크기까지 선형 보상. **오차 무관 항상 "빠를수록 +" gradient** → 정책이 물리한계까지 가속(그게 2.5든 1.8이든). 정지 명령(|cmd|<eps)은 0. weight +1.5. 저속 정밀도는 exp-추종이 담당(상보).
- **std 0.5→0.75**: exp 사망 지점을 err~1.5로 넓혀 중속 gradient 보강(정밀도 손실 미미: err 0.2서 0.93 vs 0.85).
- 커리큘럼: 기존 slow-step(4000 gap) 유지 — A가 각 stage를 학습가능하게 만듦(진행보상은 항상 가속 gradient 제공). (달성-게이팅 C는 A가 부족할 때 후속.)

**게이트**: flat P1(무DR) 완주 시 cmd 2.0/2.5 달성속도 재측정 — 물리최대까지 밀렸는지(≥1.5 기대). HW는 여유 있으므로 관절 포화가 새 병목이 되는 각도 확인.
