# 98. 처음부터(scratch) 다시 학습할 때의 계획 — 발견된 문제 반영 (2026-08-24)

사용자: "Scratch 부터 시작할때 학습 계획을 다시 잘 정리해봐야겠는데? 지금 발생한 문제들 해결해야할거같아"

이 문서는 **다음 세대(from-scratch) 학습의 실행 계획서**다. 확정 원칙은 [[62_policy_reward_design_review]] §1(12원칙)을 그대로 상속하고,
2026-08-24에 새로 측정된 문제 6건([[96_tracking_error_bottleneck]], [[97_c3_reward_trend_review]])의 처방을 얹는다.

> **진행 중인 ankleAB_c3 / ankleRP_c3는 이 계획의 대상이 아니다.** 두 런은 건강하고(낙상 0/8.6k iter) 변인이 통제돼 있어
> AB↔RP 질문에 답을 낸다. 발견된 문제는 두 arm에 **동일하게** 작용하므로 비교의 타당성을 해치지 않는다 → **완주(32k) 권고**.
> 아래 계획은 완주 후 착수한다.

## 2. 바꾸지 않는 것 (확정 원칙 상속)
- **2단계 구조 유지**(원칙 12): Phase 1 = flat·DR off, Phase 2 = DR 램프. flat·rough 양쪽에서 재현된 유일한 구조.
- 리워드 스택의 **층 순서**(원칙 5·6): 충격 cap → thermal → 위상/air_time → push-off. 순서 역전 금지.
- `pose` std 상태 분리(원칙 10), 게인은 링크 관성 기준 under-damped Kd(원칙 11), 직접 토크 보상 금지(원칙 7).
- **검증된 베이스라인 우선**(원칙 9) + **기여도 회계**(원칙 13): 총 리워드의 0.1 % 미만 기여 항은 새로 넣지 않는다.
- soft-landing(제곱 접지속도 w −1·h 0.10 + GRF 캡 420/560)은 c3에서 검증됨 → 유지([[95_soft_landing_prescription]]).
- 측정 dwell 15 s·학습 박스 전체 커버·영상 실시간 규칙 유지.

## 3. 새 스케줄 (제안)

### 3a. Phase 1 — flat, DR off, 성능 게이트형 명령 커리큘럼
| stage | vx | vy | yaw | 진급 조건 |
|---|---|---|---|---|
| S0 | ±0.8 | ±0.5 | ±0.5 | — (시작) |
| S1 | ±1.2 | ±0.6 | ±0.8 | 아래 게이트 |
| S2 | ±1.6 | ±0.7 | ±1.0 | 〃 |
| S3 | ±2.0 | ±0.85 | ±1.0 | 〃 |
| S4 | −2.0/+2.5 | ±1.0 | ±1.0 | 〃 (최종, 최소 4,000 iter 체류) |

**진급 게이트**(전부 동시 충족, 100-iter 이동평균):
1. `error_vel_xy_steady` ≤ 직전 스테이지 정착값 × 1.10 — 즉 **새 범위에 적응 완료**
2. `Episode_Termination/fell_over` ≤ 0.005
3. 최소 dwell **800 iter**, 최대 dwell **3,000 iter**(초과 시 강제 진급 + 로그 경고)

근거: c3에서 warm-start 적응은 <20 iter인데 고정 4,000 iter는 3,980을 놀렸다([[97_c3_reward_trend_review]] §3).
반대로 from-scratch는 2026-07-10에 실제 계단응답이 관측됐다 → **고정 스텝이 아니라 조건으로** 해결한다.
선례: legged_gym `update_command_curriculum`(추종 보상 >80 %일 때 범위 확장), walk-these-ways grid-adaptive
([[2026-08-24_command_box_lateral_survey]]). 예상 P1 길이 **8k–14k**(기존 고정 20k 대비 단축).

### 3b. Phase 2 — DR 램프 + 최종 소화
- DR 0 → 1.0을 **P1 종료 후 8,000 iter**에 걸쳐(=`PYG_DR_START_ITER`/`PYG_DR_END_ITER`를 P1 실측 길이에 맞춰 설정).
  ⚠ 과거 사고(2026-07-15 uneven2): P1이 짧으면 글로벌 카운터가 start_step에 못 미쳐 **DR이 0.33에 고착**. P1 길이가 가변이 되므로 **런처가 자동으로 두 값을 계산**해야 한다.
- DR 만배 후 **4,000 iter 소화**(명령·DR 모두 최종). 총 P2 ≈ 12,000.
- **entropy 어닐링**: P2 시작부터 종료까지 `entropy_coef` 0.01 → 0.002 선형(P3 처방). σ가 배포 조건(결정론)에 수렴하도록.

### 3c. 총량
P1 8k–14k + P2 12k = **20k–26k iter**(기존 32k). 16384 env·단독 3.2 s/iter 기준 **18–23 h/arm**, AB·RP 동시(4.9 s/iter)면 **27–35 h**.

## 5. 측정·보고 프로토콜 (처음부터 이걸로 고정)
1. **학습 중**: 게이트마다 `snapshot_review.py` 판정행 + **내장 평가기 축소판**(3시나리오×32 env, CPU 8분/arm — 추종·성공률·stall 판정) + `impact_probe`(200 Hz 충격량) + `dr_factor`·`lin_vel_x_max` 동시 기록.
   ⚠ **단일 롤아웃 프로브(`hack_check`/`measure_loads`)를 판정 게이트로 쓰지 말 것** — 블록을 리셋 없이 이어 붙이고 단일 env라 한 명령에서 stall하면 다음 블록이 오염된다. 2026-08-24에 이 때문에 "RP 스윙 0.039 → 두 arm 재시작" 오판을 낼 뻔했다(실제 0.052, 평가기 96 에피소드에서 stall 0). [[95_soft_landing_prescription]] §7b.
2. **완주 후**: **mjlab 내장 `src/mjlab/tasks/velocity/scripts/evaluate.py`** — 명령 고정·결정론 정책·warmup 2 s 제외·8방위 격자·mean/RMS/max. 손수 만든 프로브는 보조로만.
3. **하중**: `measure_loads.py` fc/fcp(15 s dwell, 학습 박스 전체), §7 모터 활용은 **T-N 대비**로.
4. **지표 표기 규칙**: 논문·노트에는 `error_vel_xy_steady`(결정론)를 쓰고, legacy `error_vel_xy`는 "2.5× 스케일된 학습 지표"라고 명기한다.
5. **시드**: 최소 2시드(최종 승자 arm은 3시드) — 지금까지 전부 단일 시드였다.

## 6. 착수 순서 (체크리스트)
1. ⬜ c3 두 arm 완주(32k) + fc/fcp 측정 + AB/RP 비교 노트 — **현재 진행 중**
2. ⬜ P4(T-N torque_limit) 연구 노트 → 구현(플래그) → +800 iter A/B
3. ⬜ P6 원인 측정(어느 관절이 한계를 치나, 어느 명령에서 미끄러지나)
4. ⬜ P2(게이트형 커리큘럼) 구현 + P3(entropy 어닐링) 연구 노트
5. ⬜ 런처(`run_training.sh`)에 P1 가변 길이 → DR start/end 자동 계산 추가
6. ⬜ 스모크 런(1024 env·1,500 iter)으로 게이트 전이·DR 계산·새 지표 동작 확인
7. ⬜ 본 런 착수(AB·RP 동시, 2시드)

## 7. 열린 결정 (사용자 판단 필요)
- **c3를 끝까지 돌릴 것인가, 지금 중단하고 새 계획으로 갈 것인가.** 권고는 **완주**: 발견된 문제가 두 arm에 동일하게 작용해 비교는 유효하고, 남은 20k는 약 28 h다. 중단하면 16 h가 매몰되지만 새 계획을 하루 먼저 시작한다.
- **rough 지형을 이번 세대에 넣을지**: 현재 계획은 flat 전용. rough를 넣으면 P1/P2 각각 +8k 정도.
