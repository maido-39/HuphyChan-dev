목업 B — 좌측 Scenario 탭 + 전제조건 체크리스트

전환은 액션(동사) 항목을 눌러 시작하고, 펼치면 그 조합에 필요한 3개 축(뷰어 모드/TX/로봇 프로그램)을 하나씩 개별적으로 충족시키는 체크리스트가 나온다. 상단의 "현재" 표시는 여전히 실제 상태에서 계산되며, 체크리스트를 다 채웠다고 해서 자동으로 "선택됨"이 되는 게 아니라 실제로 세 축이 맞아떨어져야 이름이 뜬다.
개선 이력 — 라운드별 발견 5개 + 조치 (펼치기)
Round 1 — 클릭수·정직성·재기동가정·탭계층·위험경로 이원화
발견 (벤치 시나리오에 대입):
  • 반복 전환 클릭수 — S3→S1 전환 1회에 최소 6클릭(탭은 이미 열려 있다 쳐도: 펼치기 → 모드 전환 → TX 무장 → 위험모달 확인 → 자동전환 실행). 무릎 1개 모터만 실물인 벤치에서는 같은 조합을 하루에도 여러 번 오간다 — 이 6클릭이 반복 비용으로 누적된다.
  • 로봇 확인 축이 "모름"으로 방치되는데, 사람이 스스로 "완료함"을 누르면 실측 확인과 동일하게 초록 ✓로 표시됐다 — 11관절 텔레메트리가 애초에 없는 벤치에서는 SSH 성공 여부를 코드가 검증하지 않고 "종료코드 0"이라 로그에 못박아 두면서도 실제로는 리드백이 없다. 자기신고와 실측 확인이 화면에서 구별되지 않았다.
  • 뷰어 재기동 시 TX 무장·확인 토큰이 초기화되는 벤치 특성을, 목업 초기 상태가 거꾸로 가정 — 첫 로드부터 TX 무장 + 로봇 확인됨으로 시작해 "이미 실물 동시 구동 중"처럼 보였다. 실제로는 재기동 직후엔 아무것도 무장돼 있지 않다.
  • Scenario 탭이 Model/Telemetry 등 5개 관측/설정 탭과 같은 층위 — 게다가 Scenario 탭을 벗어나면(Telemetry·Status를 보러 가면) 현재 조합 이름·custom 여부가 화면에서 완전히 사라진다.
  • 위험(토크 ON) 진입 경로가 두 갈래였다 — 체크리스트의 "TX 무장" 버튼은 전용 모달을 거치지만, 상단바 TX 칩을 직접 클릭하는 지름길은 브라우저 기본 confirm()만 거치고 로봇 확인 상태를 전혀 보지 않았다. 오조작으로 토크를 켜는 두 번째 경로가 있었던 셈.
조치:
  • 열린 항목마다 "일괄 진행" 버튼 추가 — 모드→로봇→TX 순서(안전한 순서, 위험 축은 항상 마지막)로 자동 적용하되 TX 무장 단계는 절대 건너뛰지 않고 항상 위험 모달을 띄운다.
  • 자동 SSH 전환에 가상 지연(≈1.4초, "SSH 실행 중…"으로 그 축만 잠금)을 넣고, 완료 시 로그에 "리드백 없음"을 계속 명시. 옆에 "실패로 표시 (모의)" 버튼을 추가해 불일치 상태가 실제로 어떻게 보이는지 언제든 시연 가능.
  • 이 목업의 초기 상태를 TX 해제 + 로봇 확인 "모름"(재기동 직후 가정)으로 바꿈 — 무장된 채 시작하지 않는다.
  • 상단바에 항상 보이는 시나리오 칩을 추가(파생값, custom이면 개수까지) + 왼쪽 탭을 "설정/전환/관측" 3그룹으로 나누고 Scenario 탭에만 amber 강조를 줌.
  • 상단바 TX 칩 클릭과 체크리스트의 "TX 무장"이 같은 위험 모달 함수를 타도록 통합. 로봇 확인이 "확인됨"이 아니면 모달에 동의 체크박스가 추가로 나타나고, 체크 전에는 확인 버튼이 비활성 — 위험이 겹치는 경우에만 클릭 한 번을 더 요구한다(비례 마찰).
Round 2 — Round 1이 새로 만든 문제 위주 (일괄진행 은폐 에스컬레이션· 전역 대기슬롯·실패 상태의 과장)
발견:
  • "일괄 진행" 버튼이 클릭마다 다른 일을 하는데 겉모습은 똑같았다 — 1번째 클릭(모드 맞추기+로봇 전환 시작)은 무해하지만, 로봇 전환이 끝난 뒤 같은 버튼을 같은 자리에서 같은 글자로 한 번 더 누르면 그게 바로 TX 무장 위험 모달을 여는 클릭이다. "이 버튼 누르다 보면 끝난다"는 습관이 들면 위험 확인 앞에서 멈추게 하려던 원래 취지를 우회하게 된다.
  • robotSwitchPending이 전역 슬롯 하나 — S1 전환이 진행 중일 때 S2를 열어 "자동 전환 실행"을 누르면 S1의 진행 상황이 아무 로그도 없이 조용히 사라졌다(벤치 SSH 세션은 하나뿐인데 두 번째 요청이 첫 번째를 말없이 덮어씀). S1을 시작한 사람은 그게 왜 안 끝났는지 알 방법이 없다.
  • "실패로 표시(모의)"가 상태를 '불일치'로 만들었는데, 실패한 SSH는 "다르게 실행 중"이라는 증거가 아니다 — 재시작 실패는 보통 기존 프로그램이 그대로 살아있다는 뜻에 더 가깝다. Round 1이 도입한 이 버튼 자체가 3상태(확인됨/모름/불일치) 정직성 원칙을 스스로 어기고 있었다: "모름"이어야 할 상태를 "불일치"(적극적으로 다르다는 근거가 있음)로 과장.
  • 동의 체크박스가 robotConfirm !== 'confirmed'로만 켜졌다 — 로봇이 "확인됨"이지만 이번 전환이 요구하는 것과 다른 프로그램으로 확인된 경우(예: 이미 다른 정책을 확인된 채 돌리는 중)는 걸러지지 않아, 정작 명령이 충돌할 수 있는 상황에서 추가 경고가 안 떴다.
  • 안내(guided) 모드에서 모드는 맞고 로봇 확인만 남으면, "일괄 진행"을 계속 눌러도 매번 같은 안내 로그만 반복 — 진행이 안 된다는 신호가 버튼 자체엔 없고, 실제로 눌러야 할 아래쪽 SSH 복사박스로 시선을 끌지도 않는다.
조치:
  • "일괄 진행" 라벨과 색을 다음 클릭이 실제로 할 일에 맞춰 매번 다시 계산 (→먼저 모드 전환 / →로봇 자동 전환 시작 / →⚠ TX 무장 확인창 열기(위험색) / →TX 해제 적용) — 위험한 클릭만 눈에 띄게 다르게 보인다.
  • 다른 축이 이미 전환 중이면 새 전환 시작을 거부하고 로그에 사유를 남긴다("벤치 SSH 세션은 하나뿐"). 다른 항목을 열어도 "○○ 전환 진행 중이라 대기"만 보이고 새로 시작할 수 없다.
  • "실패로 표시(모의)"가 이제 확인 상태를 '불일치'가 아니라 '모름'으로 되돌린다 — 실패는 확인이 안 됐다는 뜻이지 다른 걸 실행 중이라는 뜻이 아니므로.
  • 동의 체크박스 조건에 "확인됨이지만 이번 전환이 기대하는 프로그램과 다름"도 추가하고, 그 경우 체크박스 문구가 어떤 프로그램이 실행 중인지 구체적으로 말한다.
  • 안내 모드에서 로봇 확인만 남았을 때 "일괄 진행" 버튼을 비활성화하고 라벨을 "일괄 진행 불가 — 안내 모드: 로봇 확인 직접 하기"로 바꿔, 반복 클릭이 아무 것도 안 한다는 사실 자체를 숨기지 않는다.
